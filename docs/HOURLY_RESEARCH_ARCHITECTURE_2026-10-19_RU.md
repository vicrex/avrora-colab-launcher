# AVRORA — единая архитектура автономного исследовательского контура
**Версия:** 2026-10-19 / DESIGN-FROZEN-01  
**Статус:** реализация в черновом PR, не эксплуатационная готовность.  
**Принцип:** сначала полный проверяемый цикл, затем включение часового расписания. Любая ошибка = остановка, а не оптимистичный отчет.

## 1. Целевая схема (поток данных и результатов)

```text
Версионированный приватный набор свечей (SHA256, обнаружение свежих снимков)
            |
            v
Каталог гипотез + immutable prereg (до чтения результатов)
            |
            v
Очередь состояний [NEW -> REGISTERED -> CLAIMED -> VERIFIED / REJECTED / BLOCKED]
            |             (leases + no duplicate committed result)
            v
Часовой координатор GitHub Actions (одна задача за тик, bounded budget)
            |
            v
Приватный Colab CPU worker (REAL=OFF, HOLDOUT=SEALED)
       |                                  |
       v                                  v
Движок A: сигналы + портфельный         Движок B: независимые сигналы +
бэктест (каузальность, стоп-первый)      полная пересборка сделок
       |                                  |
       +---------------CHECK2-------------+
                       |
             строгая field-by-field сверка
                       |
               fail closed / result
                       |
    подписанная метаданными квитанция:
    source SHA, prereg SHA, code SHA, CHECK2,
    costs20/25, trades, net, PF, frequency,
    OOS false/true, run_id, ZERO-ORDERS
                       |
          защищённое долговечное хранилище
          + повторное чтение + ACK
                       |
              отчёт (USDT/день,
                6 инструментов, причины отказа)
```

## 2. Границы доступа и безопасности

1. Приватные свечи, код и торговые данные **не публикуются** в `vicrex/avrora-colab-launcher`, логах и публичных артефактах. Приватный read-only deploy key разрешён только к `vicrex/avrora-wave-source`; для Colab — отдельный минимальный OAuth. Никакого Drive-wide допуска.
2. `REAL=OFF`, `HOLDOUT=SEALED` и отсутствие API отправки ордеров. Любая несанкционированная переменная/источник/неизвестный кандидат останавливает цикл.
3. Приватные данные восстанавливаются только в ephemeral runner/Colab, сверяются с замороженным SHA256 и удаляются после запуска, включая credentials.
4. May/July 2026 P900 — ранее использованная **discovery**, не OOS; запрещено выдавать её за свежий OOS или доказательство прибыли.
5. Экономика: 20 и 25 bps круговых расходов, неблагоприятный gap, STOP_FIRST, лимит двух одновременно открытых позиций и одной на символ, максимальный notional 500 USDT и stop-risk 5 USDT; funding/slippage/maker fill пока не доказаны. Риск на gap может превысить стоп-лимит: отдельно учитывать факт.
6. На прибыльные статусы влияет не только PF, но и число сделок, USDT/день, устойчивость по неделям и инструментам; никакого автоматического допуска REAL даже при положительном discovery.

## 4. Порядок внедрения и точные критерии завершения

**G0 — Архитектура и frozen prereg:** документ и кандидатные спецификации записаны в git; нет изменения критериев после просмотра результата. Отдельная ветка и черновой PR.

**G1 — Локальная проверка:** движок A + независимый B совпадают на всех сигналах и всей истории сделок на синтетике. Adversarial tests на future leakage, стоп/тейк коллизии, gap, портфель, fees, tamper. GitHub Actions CI зелёный. Независимые алгоритмы без импортов друг друга.

**G2 — Реальный приватный discovery:** один явно идентифицированный кандидат, SHA-checked source, удалённый Colab CPU, CHECK2=PASS, receipt SHA, защищённый readback. Публичный проект получает только ограниченные агрегаты. Сохранить параметры, исходники и результаты без утечек.

**G3 — Состояния и повторяемость:** один входной prereg+data SHA обрабатывается однократно, повтор выдаёт `IDLE_NO_NEW_APPROVED_CANDIDATE`; журнал устойчив к рестарту и конфликтам, без потери задач.

**G4 — Независимая оценка:** fresh dataset с отделённой validation-схемой; holdout открывается только через заранее одобренный процесс. Качество maker fill / funding / slippage явно определено. Discovery не равен валидированному OOS.

**G5 — Планировщик:** только после G0–G3 включить best-effort `cron: "17 * * * *"`; ограничение ресурса/ошибок, отсутствие повторных нагрузок и оповещение на BLOCKED. После G4 возможен более строгий статус кандидата, но никогда автоматический REAL.

## 6. Правило принятия решения

«Подключено» означает минимум **G0 + G1 + G2 + G3 + G5**, при этом G4 может оставаться отдельным статусом «нет OOS», который должен явно отражаться во всех отчётах. До этого — «в разработке», даже если отдельные тесты зелёные. Любая найденная ошибка исправляется до дальнейшей интеграции, без добавления новых функций и смены цели.
